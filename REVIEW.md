# Review instructions

## Severity

Important is for: auth or authz bypass, cross-tenant access, leaked secrets
or personal data (logs, audit logs, webhooks, errors, responses), broken
login/registration/MFA flows, and breaking changes to APIs, config,
`frontend-sdk` or `hanko-elements`. Everything about style, naming or
refactoring is Nit at most. Report at most five Nits.

## Do not report

- Formatting
- `backend/json_schema/*.json` (generated by CI) and lockfiles
- `frontend/examples/`, unless the change breaks SDK usage
- Fake secrets in test fixtures and e2e seed data

## Always check

- Tenant scoping: every new record, lookup, search and existence check uses
  the tenant ID from the tenant middleware.
- Database portability: queries, migrations and column types must work on
  PostgreSQL, MySQL, MariaDB and CockroachDB, and string columns must fit
  the input that reaches them. Every `.up.fizz` needs a working `.down.fizz`.
- Inside `Transaction(func(tx ...))`, persisters use
  `Get...PersisterWithConnection(tx)`.
- Every path that changes user data, including the admin API, triggers the
  matching webhook, audit log entry and security notification, and respects
  tenant config and privacy settings.
- Third-party and SAML: strict redirect allowlist matching, case-insensitive
  emails, unverified provider emails never linked to existing accounts.
- New config fields: `jsonschema` default matches `config_default.go`, plus
  a doc comment (both feed the generated config reference).
- New UI strings are translated in every locale in
  `frontend/elements/src/i18n/`, not copied from `en.ts`.
